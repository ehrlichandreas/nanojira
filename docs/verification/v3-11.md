## 1. Diff review

**`tools/export-skill.mts`** (full read): resolves the repo from `cwd`
(`git rev-parse --show-toplevel`), never its own path. `git` is called
only via `execFileSync('git', [...], { cwd })` — grepped the whole file
for any shell invocation (`exec(`, backticks, `shell: true`): none.
Step order matches the spec exactly: (1) `git tag -v <tag>` before
touching `<dest>` at all; (2) every shipped file read via `git show
<tag>:<path>`; (3) built at a sibling temp path
(`.export-skill-<dest>-<pid>-<ts>`) in `<dest>`'s own parent directory,
then `fs.renameSync` into place — same filesystem, atomic; (4) an
existing `<dest>` is refused unless it has its own `VERSION` file,
checked *before* any temp-directory building starts. Every write is
`fs.writeFileSync`/`fs.chmodSync`; grepped for `symlinkSync`: none
anywhere in the file.

**The wrapper templates** (`WRAPPER_SH`, `WRAPPER_CMD`, embedded string
constants in `export-skill.mts`): one template for both binaries,
parameterised only by `basename "$0"` / `%~n0`. `dirname "$0"` +
`cd -P` resolution, `CDPATH=''` guard. `NJ_NODE` or `node` from `PATH`,
existence via `command -v`/`where`, version floor exactly 24 via a
plain-text parse of `--version`+`sed`/batch `for /f`. `unset
NODE_OPTIONS` before `exec`. Entry is `$dir/../dist/$name.mjs`, checked
with `[ -f ]`/`exist` before exec. Every failure path: exactly one
stderr line, exit 127.

**`tools/bundle.js`**: `format: 'esm'`, writes `dist/nj.mjs` /
`dist/nj-mcp.mjs`. The `nodeOnlyImports` esbuild plugin resolves every
non-relative import, rejects anything not in `node:builtinModules`
(build error, not a warning), and rewrites every surviving import to
its `node:`-prefixed form regardless of source spelling. `checkStrict`
additionally guards against esbuild silently folding a non-`'use
strict'` module into the entry's scope. `--check` is a real
byte-identity check against a fresh in-memory build.

**`src/nj-mcp.ts`**: sibling resolved as
`path.join(path.dirname(path.resolve(process.argv[1])), 'nj.mjs')` —
fixed name, no extension-matching logic left (D179's rule is retired,
per addendum 9b3d0de, now that the bundle has exactly one shipped
extension). No `existsSync` pre-check on `njPath`; a missing sibling is
left to node's own `Cannot find module` failure in the spawned child,
surfaced through the existing `close` handler as a clean JSON-RPC
`-32603 Internal error` naming the missing path — confirmed this is
the intended design (not an oversight) by reading AC-32's M12b comment,
which explicitly tests for exactly this shape of failure rather than a
pre-flight check.

**`tools/refactor-harness/gate.js`**: `NJ` resolution now tries
`dist/nj.mjs` first, falls back to the extensionless `dist/nj` (so a
replay of a pre-v3.11 tag/commit keeps working), defaulting to the
`.mjs` name only when neither exists yet. `--nj=<path>` targets
whichever of the two the checked-out step already has. This is the
entire functional diff (31 lines, mostly comments) — confirmed by
reading the full `git diff` for this file.

**`test/lib/harness.js`**: `NJ_MCP` now derived with
`path.extname(NJ)` appended after `nj-mcp`, so it correctly produces
`nj-mcp.mjs` next to `nj.mjs`, or bare `nj-mcp` next to an old
extensionless `nj` — both directions preserved.

**`test/lib/mcp-stdio.js`**: `request()` now rejects every
still-pending call promptly when the child process exits (`error` or
`close`), instead of leaving each to its own fixed timeout — read in
full; the `exited` guard also makes a `request()` placed *after* the
child already died fail immediately. This is what lets AC-32's M12b
(missing-sibling case) fail cleanly within its own suite instead of
risking an unhandled rejection at `mcp-stdio.js`'s internal timeout.

**`tools/release-local.sh`**: removed (`git log` confirms it exists
only in history from `40dd596` on); matches D185's "Retired" clause.

**`package.json`/`tsconfig.json`/`tools/perf.js`**: version bump,
`bin` entries retargeted to `dist/*.mjs`, `tsconfig.json` now includes
`tools/**/*.ts` and `tools/**/*.mts` (type-checks the export tool),
`perf.js`'s hardcoded path updated. All mechanical, no behaviour change
beyond the extension.

**Spec/implementation wording check (found, then fixed this round):**
SPECIFICATION.md § 18 documents the wrapper's "node missing" stderr
line as `` `<name>: node not found (looked for '<NJ_NODE or "node">')` ``.
At `40dd596`, both `WRAPPER_SH` and `WRAPPER_CMD` only emitted the bare
`<name>: node not found`, with no "(looked for …)" suffix — AC-56's W5
used a loose regex (`/node not found/`) that didn't catch the missing
suffix. Reported to the Lead; fixed properly rather than just
documented: `c068edf` tightened W5 to an exact stderr match naming the
actual `NJ_NODE` value, `fff9fc0` added the suffix to both templates.
Re-verified after the fix (§ 4 below).

## 2. Live repro in `/tmp`

`~/.gnupg` regardless of `GNUPGHOME` — overridden per-invocation via
`GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=gpg.program
GIT_CONFIG_VALUE_0=gpg` (highest git config precedence, no permanent
repo-config change) so `git tag -v`/`git tag -s` actually used the
throwaway keyring. Tagged `40dd596` as `verifier-scratch-40dd596`
(signed), plus `verifier-scratch-unsigned` (annotated, unsigned) and
`verifier-scratch-lightweight` (no annotation) for negative-path
checks; all three deleted at the end of this round (§ 8).

- **`.cmd` plausibility** (no Windows run available on this machine):

## Verdict

**PASS.** `40dd596` (plus the in-round follow-up commits `9dbaddb`,
`c068edf`, `fff9fc0`, all verified individually above) implements D185
and its addenda correctly: the export tool reads only from the signed
tag, builds atomically, refuses a foreign destination, writes no
symlinks; the wrapper templates are correct on every tested axis
including the exact § 18 stderr wording; the bundle is ESM and
`node:*`-only, enforced at build time; `nj-mcp`'s sibling lookup is
simplified correctly for the single-extension world and fails cleanly,
not silently, when the sibling is missing; the gate supports both old
and new `dist/` layouts; and the gate replay shows the ESM conversion
changed zero observable behaviour versus v3.10. Three real AC-56
coverage gaps surfaced by mutation testing (working-tree-vs-tag,
`NODE_OPTIONS`, version floor) and one spec/implementation wording
drift were found, reported, fixed (not merely documented), and
independently re-verified before this verdict — the process this
project's verification rounds exist to run.
