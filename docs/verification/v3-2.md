### F1 — high, regression: a type or archive folder that is a directory symlink is silently dropped

```sh
nj init; nj new --type=epic --title=E; nj new --type=task --parent=EPIC-001 --title=T
mv backlog/tasks ../shared-tasks && ln -s ../../shared-tasks backlog/tasks   # adjust the link to your layout
nj list        # V3-2: EPIC-001 only        c3/v2: EPIC-001, TSK-001
nj doctor      # V3-2: exit 0, no findings  (nothing says tasks/ was skipped)
nj new --type=task --parent=EPIC-001 --title=n   # exit 0, file written through the link …
nj list        # … and TSK-002 is not listed either
```

- `archive/` as a symlink: an archived epic vanishes from `list --all`, and
  `doctor` stays clean.
- The cause: `scanBacklog` walks the configured folders with the same rule as
  every other directory (B11: never follow a directory symlink). v2 opened
  `path.join(backlog, 'tasks')`, which follows the link.
- The result is § 4's "worst failure mode": silently 0 entries from the right
  directory, and new writes disappear.
- AC-22 B6 tests "never followed" only for a *non-configured* `linked/`.

**Expected:** B11 should cover links *below* the configured folders. The
top-level configured folders (and the backlog root, which already works)
should be followed, as v2 did. If they are not followed, `doctor` must report
them and `new`/`archive` must refuse to write into them. **Needs a ruling.**

### F2 — high: folder names are compared case-sensitively on a case-insensitive filesystem

| Case | Result (V3-2) | c3/v2 |
|---|---|---|
| (a) v2 backlog whose folder on disk is `Tasks/` (`mv backlog/tasks backlog/Tasks`) | `type:folder` error on every task. `--fix`: note "cannot move into tasks/ — target exists", repeated forever. The tasks drop out of `--ready`. | clean, tasks ready |
| (b) valid config `"layout": {"folders": {"tasks": "Tasks"}}`, disk `tasks/` | same permanent error. `nj new --type=task` creates a task that is **immediately** `type:folder` (it is written into `Tasks/`, which is `tasks/`) | (Linux: `--fix` would rename, fine) |
| (c) `archive/` on disk as `Archive/` | archived elements are **active** again (shown by `list`), `type:folder`, not fixable | archived, hidden |
| (d) `hierarchy`, folder `epic-001/` holding `EPIC-001.md` | `layout:misplaced`, "cannot move into EPIC-001/ — target exists", forever | — |

- Two causes, both from the one assumption that names are case-sensitive:
  - `scanBacklog`/`markPlaces` compare `readdir` names byte-wise with the
    configured names (`top.find(e => e.name === n)`, `want !== el.folder`).
  - `planMove` `lstat`s the target and sees the *same* inode as an occupant.
- B14 already rules that APFS/NTFS are case-insensitive, but only for config
  validation.
- (b) is the serious one: a configuration that § 5 accepts leads to a state
  that `nj` itself can neither repair nor avoid.

**Proposal:**
- Compare folder names by filesystem identity (`realpath`, or
  `stat().ino`/`dev`) rather than by string.
- In `planMove`, treat a target that is the source itself as "free, rename
  case-only". A case-only `rename` works on APFS.

Repro: `a.js A1 … A4`; (a) and (c) against `1e85263` show the c3 column.

### F3 — medium: `doctor --fix` crashes in the middle of step 3 (stale paths within one round)

```sh
# hierarchy; an epic folder, misplaced, with another misplaced epic folder inside it
backlog/foo/EPIC-001/EPIC-001.md
backlog/foo/EPIC-001/EPIC-002/EPIC-002.md
backlog/foo/EPIC-001/EPIC-002/TSK-001/TSK-001.md   (parent EPIC-002)
nj doctor --fix --json
# exit 1, internal_error, stderr: "Error: Error: ENOENT … rename 'backlog/foo/EPIC-001/EPIC-002' -> 'backlog/EPIC-002'" + stack
```

- What happens:
  - `fixStep3` reloads once per round, so every epic in the round keeps the
    path from that reload.
  - Moving EPIC-001's folder carries EPIC-002 along.
  - `planMove(stale src)` then `lstat`s only the *target*: ENOENT, so it
    plans a rename, and the rename throws.
- State left: EPIC-001 moved; steps 4–8 skipped; `foo/` left empty. A second
  `--fix` finishes the job (exit 0).
- **Expected** (§ 14 "reports the actions it took", § 11 "all targets
  verified first"):
  - re-resolve an element's path after an earlier move in the same round, or
    reload after every folder move;
  - `planMove` should fail the plan when the *source* is gone.
- `h.js H7`.

### F5 — medium: `--fix` writes into non-element `*.md` files anywhere in the backlog

```sh
mkdir backlog/docs
printf -- '---\ntitle: notes\n---\nhello\n' > backlog/docs/meeting-notes.md
echo '# changes' > backlog/CHANGELOG.md
nj doctor --fix --json
# fixed: "meeting-notes: wrote id into the frontmatter", "created 3 missing tombstones in .ids/",
#        "meeting-notes: wrote status, created, updated"
# new: .ids/CHANGELOG .ids/README .ids/meeting-notes (the README is backlog/docs/README.md, B12)
```

- D86 accepted that a stray `*.md` anywhere is *read and reported* as an
  element. It didn't say `--fix` should rewrite a human's document (`id:
  meeting-notes`, `status: todo`, timestamps) or burn tombstones named
  `CHANGELOG`/`README`.
- v2 did the same, but only inside the three type folders (v3-1 F3's second
  half). The recursive scan now extends it to `docs/`, `notes/` and so on.
- Dot-files are caught too (`._EPIC-001.md` AppleDouble, `.EPIC-001.md`
  backups, see F9).
- **Proposal:** steps 1, 4 and 5 act only on files whose name has the § 8 ID
  shape. Everything else is reported, never written.
- `s.js S3`.

### F6 — medium: `--fix` archives elements that carry no `archived:` (DECISIONS 92 Q2)

```sh
# hierarchy: EPIC-001/EPIC-001.md (todo);
# TSK-003/TSK-003.md with parent EPIC-001 and a hand-written archived: (misplaced at the top);
# TSK-003/SUB-007.md (status todo, no archived:)
nj doctor --fix --json
# fixed: "moved TSK-003 with its folder → archive/EPIC-001/TSK-003/"
# → SUB-007 (todo, unstamped) now lies in the archive: archive:not_done, exit 2
```

- `moveTarget` follows Q2 for TSK-003. But under `hierarchy` the move takes
  TSK-003's whole folder, so its live children are archived by location,
  contrary to Q2's "`doctor --fix` never … archives one". The mirror case
  un-archives stamped children the same way.
- One way to get there without editing by hand:
  - A hierarchy `archive` whose `rename` fails (e.g. `archive/` not writable,
    `f.js F6`) has already stamped `archived:` into every file *in place*
    (B16) and exits `internal_error`.
  - `doctor` then reports **nothing**: stamped files at a valid active place
    have no finding, per Q2.
  - The next layout change plus `--fix` moves those files into the archive
    (fine) or carries unstamped ones along (this finding).
- **Proposal:** under `hierarchy`, step 3 refuses a folder move whose
  subtree disagrees on `archived:` (note it, don't move). And/or
  `archived:` on a live file becomes a warning after all.
- `h.js H8`.

### F10 — low, pre-existing (v2, c3 identical): `nj new` overwrites a hand-written `TSK-001.MD`

