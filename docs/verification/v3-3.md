## Method for the replay check

`gate.js`'s displayed diff truncates at 40 entries and clips each string to
400 chars — useless for auditing 1892 diffs. In my own `/tmp` worktree copy
of the harness (not the repo's `tools/`) I raised both limits and re-ran
`baseline.js verify` directly. Confirmed the *displayed* total (1892) first,
then parsed every block and classified it against four independent,
literal-text rules (STATUS.md is the only file that appears in `after`;
`nj init`'s own diff; `status_stale`/"STATUS.md is missing or differs..." in
stdout; "regenerated STATUS.md" in stdout). Every one of the 1892 matched
exactly one rule; none were left over.

Two things worth naming precisely:

- **"init prose lists it" is a legitimate output change.** § 4 doesn't pin
  `init`'s human-readable line as normative text (unlike the JSON shapes),
  and the new word is exactly the file `init` now creates. Sampled the raw
  corpus: 41 non-`--json` `init` calls exist; the ones that differ are the
  successful ones (`exit 0`), matching "created" not "failed".
- **`status_stale` appears only where the fixture genuinely had no fresh
  file.** By construction this holds for every v2/c3 corpus fixture: none
  of them ever had a `STATUS.md` (the file didn't exist before V3-3), so
  the *first* `doctor` call against any hand-built, non-`nj`-constructed
  fixture (cycles, duplicates, golden snapshots, …) legitimately gains the
  warning. Sampled 6 directly (`ac-13`, `ac-09`, `cycle-parent-archived`,
  two `doctor`/`doctor --json` pairs) — all show exactly `backlog:status_stale`
  appearing, nothing else, consistent with "missing before, freshly written
  now".

## Findings

### F1 — medium, procedural: `gate.js --frozen=oracle-frozen-8` exits 8 (VERDICT RED), unmentioned by the commit

`node tools/refactor-harness/gate.js --step=cca6aa3 --frozen=oracle-frozen-8`
(harness at HEAD, includes the Toolsmith's I1–I8 verdict-gating fix):

```
replay: exit 8
oracle: no summary, exit 1
gate  : exit 8, VERDICT RED: a suite or check failed
```

The replay's own "RED VERDICTS" section names 16 **frozen** oracle suites
(`ac-03`, `ac-09`, `ac-11`, `ac-13`, `ac-18`, `ac-19`,
`archive-rm-byte-identity`, `cycle-parent-archived`, `cycle-parent-shapes`,
`exit-doctor-fix`, `exit-fault-vocabulary`, `fix-duplicate-mtimes`,
`order-doctor-problems-severity`, `state-cycle-all-members`,
`tombstone-partial-loss`, `unreadable-stub-refusals`) — these are
`oracle-frozen-8`'s **pre-V3-3** copies, run as part of the replay's own
byte-collection pass. I ran 5 of them directly against `cca6aa3:dist/nj`:

```
edge/archive-rm-byte-identity.js — 3 of 59 failed
  ✗ rm: no unexpected file appeared        ["STATUS.md"]
edge/exit-doctor-fix.js — 4 of ... failed
  ✗ … findings before --fix are exactly § 7's set
    UNEXPECTED ["backlog:status_stale:warning"]
ac/ac-13-json-contract.js — 2 of 202 failed
  ✗ every code seen comes from the closed table of § 7
    not in the table: ["backlog:status_stale"]
ac/ac-09-atomicity.js — 2 of 24 failed  (same status_stale pattern)
edge/cycle-parent-archived.js — 1 of 5 failed  (same pattern)
```

Every one fails purely because it hard-codes "no file but these appears" or
"exactly these findings" from before `STATUS.md` existed — exactly the
intended, documented change. This is **not** a defect in `cca6aa3`.

**But it's a real gap.** DECISIONS 90 B1's worktree procedure was built for
a *suite-adding* step (V3-1's AC-21): replay the frozen suite unmodified,
then run the new suite separately. V3-3 is a *behaviour-changing* step: the
frozen suites themselves, unmodified, can no longer pass — not because
`nj` regressed, but because they encode assumptions the step intentionally
retires. `gate.js` has no way today to tell these two situations apart; it
gates hard on any frozen-suite failure regardless of cause. The commit
message's "Replay: … 1892 differing calls, all in four named classes …
Nothing else differs" describes the byte-diff half correctly but says
nothing about the exit code or the 16 red suites — someone reading only the
commit could reasonably believe `gate.js` returned a clean result.

**Recommendation:** either (a) extend `gate.js` with a documented way to
mark specific frozen suites as "known-stale for behaviour-changing step
X" (with the reason and the confirming direct run, as above, checked in),
or (b) for a step like this, judge conformance from the replay's **byte
diff** (which stayed correct, per the classification above) plus the
step's own `test/` run (step 5, which was clean), and treat the replay's
own-suite RED VERDICTS as informational rather than gating for this one
class of step. Either way the commit should state the gate's actual exit
code rather than omit it.

### F2 — low, informational: `STATUS.md` publishes the still-open case-insensitivity bug's symptom

DECISIONS 105 already rules (unfixed as of this commit — confirmed:
`grep -n "toLowerCase\|case-insensit" src/core/layout.ts` finds nothing)
that folder-name matching must become case-insensitive; until it does, a
configured `archive` folder that's actually named `Archive/` on disk isn't
recognised as the archive, so elements below it are read as **active**
even though they carry `archived:` and are genuinely done.

```sh
nj init; nj new --type=epic --title=E1 --description=d
nj set --id=EPIC-001 --status=done; nj archive --id=EPIC-001
mv backlog/archive backlog/Archive       # case-only rename
nj list --json         # [ "EPIC-001" ] -- ALREADY leaks pre-V3-3, at 9fa11d9 too (checked)
```

This part is nothing new. What's new: `doctor --fix` now also **writes
this wrong state into the committed `STATUS.md`** —

```
## done (4)

- [EPIC-001](Archive/EPIC-001.md) E1
- [SUB-001](Archive/SUB-001.md) S1
- [TSK-001](Archive/TSK-001.md) T1
- [TSK-002](Archive/TSK-002.md) T2
```

— four items a reader would see in an editor or a forge's web view as
"active, done, ready to archive", when they're already archived. Same
underlying cause also explains the +10 new failures in
`edge/v3-2-regressions.js` (61→71) and a few in `coverage-v3-gaps.js`: both
suites assert `doctor --fix` is a **total no-op** on an already-fixed,
already-archived backlog; pre-V3-3 that held vacuously (there was no
`STATUS.md` to regenerate), post-V3-3 step 9 legitimately rewrites the file
to reflect the (wrongly-active) elements, breaking the "no-op" assertion.
Not a `cca6aa3` defect — `--fix`'s regeneration is doing exactly what it
should with the information `layout.ts` currently gives it. Worth raising
the priority of the still-open D105 case-insensitivity fix, since its
blast radius just grew from "silent, ephemeral" (only visible via `list`)
to "silent, committed" (baked into a file a human is meant to trust without
running `nj`).
