## 1. Diff review

- **`tools/wrapper.sh`/`tools/wrapper.cmd`** — new template files. Read in
  full: identical launcher logic to v3.11's embedded `WRAPPER_SH`/
  `WRAPPER_CMD` string constants — `dirname "$0"`/`CDPATH`-safe
  resolution, `NJ_NODE` or `node` from `PATH`, a plain-text version-floor
  parse (no JS eval), `unset NODE_OPTIONS`, entry at
  `$dir/../dist/$name.mjs`, exit 127 with exactly one stderr line on any
  failure, a final `exec`. No behavioural change from v3.11, only a move
  from inline strings to real files `bundle.js` now reads.
- **`tools/bundle.js`** — rewritten around `DIST_TARGETS`/`BIN_TARGETS`
  arrays and the two template files. `checkStrict` now accumulates into a
  `problems` array instead of exiting on the first mismatch; a new
  `checkSkillMd` regex-parses `SKILL.md`'s frontmatter (`name`,
  `description` ≤ 1024 chars, `license`, nested `metadata.version` against
  `package.json`'s version). Read the full source: the `problems.length`
  early-exit happens strictly before either write loop, so a build that
  finds any problem writes nothing — confirmed both by code structure and
  empirically (§ 2). `--check` verifies `dist/*` by `Buffer.equals`,
  `bin/*` by string equality, and additionally the executable bit
  (`mode & 0o111 !== 0`) for the two `mode: 0o755` targets (`bin/nj`,
  `bin/nj-mcp`).
- **`tools/export-skill.mts`** — rewritten: no more embedded wrapper
  constants. `isOwnExport()` reads the destination's own `SKILL.md` and
  checks `name: nj` for the foreign-dest refusal (replacing the old
  `package.json`-name check). The exported version is parsed from the
  `SKILL.md` buffer actually being exported (not from `package.json`).
  `show()`/`write()` now touch exactly `SKILL.md`, `bin/nj`, `bin/nj-mcp`,
  `bin/nj.cmd`, `bin/nj-mcp.cmd`, `dist/nj.mjs`, `dist/nj-mcp.mjs` — seven
  files, no `VERSION`. The signed-tag check and the atomic rename are
  unchanged from v3.11.
- **`test/lib/harness.js`** — `isDirectExec(p)` (no `.mjs`/`.cjs`/`.js`
  extension) now decides, per path, whether to run it directly (a `bin/`
  launcher, which reads `NJ_NODE` itself) or as `<NODE> <path>` (a bare
  bundle). `NJ_BUNDLE` always resolves to the `dist/*.mjs` sibling
  regardless of whether `NJ` under test is `bin/nj` or already a bundle —
  used by `det-id-retry.js` (the shim-preload suite must bypass the
  launcher's deliberate `NODE_OPTIONS` strip) and by `hardening-v3-1.js`'s
  D96 cwd legs (strict against the bundle; a separate, explicitly
  bin/nj-specific block, guarded by `H.NJ !== H.NJ_BUNDLE`, is tolerant of
  the extra `/bin/sh` "shell-init" line real `bin/nj` picks up, strict on
  the exit code and the LAST stderr line). `copyShippedUnit()` copies the
  whole release tree (`SKILL.md`+`bin/`+`dist/`) for a direct-exec `NJ`,
  or the two bare `.mjs` files for a bundle path — exercised by
  `ac-38-mcp-no-dependencies.js`'s "no `node_modules` beside the shipped
  unit" check. `test/lib/mcp-stdio.js`'s `spawnServer` now dispatches
  through this same `njCommand`, fixing a hard break against `bin/nj-mcp`
  (previously hardcoded `spawn(process.execPath, [njMcpPath, …])`, a
  `SyntaxError` against a shell script). `test/run-all.js` defaults `NJ`
  to `bin/nj` when neither the `NJ` env nor `argv[2]` is given.
